# Primary Teacher Runtime acceptance checklist

Use this checklist for architecture review, synthetic replay, and later real-child observation.

- [ ] Child performs observable thinking between substantial teaching chunks.
- [ ] Wrong answer does not mechanically trigger reteaching.
- [ ] Isolated lapse can remain a transient session hypothesis when prior evidence supports that interpretation.
- [ ] `SkillState` and `CurrentLearningState` are represented separately.
- [ ] Conceptual support is not conflated with language/access support.
- [ ] Representation evidence can distinguish provided, child-selected, and child-produced use.
- [ ] Two failed attempts using substantially the same teaching route trigger a meaningful route change.
- [ ] Repair is followed by an independent retry when appropriate.
- [ ] Worked-example success is not counted as independent evidence.
- [ ] Immediate game performance is not treated as delayed retention or durable mastery.
- [ ] Acquisition, independent use, delayed retention, transfer, and stretch remain independent evidence dimensions.
- [ ] Source simplification/ambiguity is represented explicitly rather than force-fit into invented source categories.
- [ ] Child-facing explanations use taught language and provide a reusable recognition cue or next move.
- [ ] Support can fade when evidence permits.
- [ ] The runtime can end, defer, or change activity rather than continuing indefinitely.
- [ ] Backend/provider selection has no effect on educational interpretation.
