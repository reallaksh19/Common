### Active hypothesis

A compact repo-wide traffic/index log plus immutable chain-scoped endpoint files reduces write collisions while preserving the user's required relay behavior: the latest durable endpoint already contains the inputs, benchmarks, common/governing documents, next action, protected authority, and five questions needed by the next agent even when the previous agent disappears abruptly.

### Falsifier

The architecture is falsified or requires redesign if a real pilot shows any of the following: two independent chains routinely conflict on endpoint files; an incoming engineer must use chat to reconstruct essential intent; an orphan endpoint cannot be safely reconciled; the compact index can silently point to stale/wrong-chain custody; the five questions become generic/retrospective; or a syntactically valid but fabricated candidate answer can obtain write authority without substantive verifier evidence.

### Protected invariants

- Repository/live Git truth outranks relay metadata.
- Graceful outgoing-agent handoff is optional.
- Detailed durable endpoint files are immutable; corrections occur through later endpoints.
- Exactly five questions exist at every non-terminal endpoint and test the next unresolved leg.
- Inputs, benchmarks, common/governing documents, authoritative sources, production paths, and validation paths remain explicitly indexed at every endpoint.
- Candidate self-verification never grants engineering-critical write authority.
- `NOT_RUN` remains explicit.
- Engineering evidence/oracle/authority anti-gaming rules from v1 are not weakened.
- PR merge does not imply engineering-chain completion.
