### Active hypothesis

Separating immutable agent proposals from Owner-controlled roadmap files, while requiring exact roadmap blob binding before coding, will keep strategic direction stable without turning roadmaps into stale unquestioned truth or high-contention agent-maintained status files.

### Falsifier

The architecture is falsified if an agent can start a version-2 material coding leg without explicit roadmap discovery/binding, if AUTO/merge authority can be interpreted as roadmap-write authority, if stale roadmap status overrides live repository truth, or if independent chains must edit one shared roadmap merely to report routine progress.

### Protected invariants

- Owner controls roadmap mutations.
- Roadmap planning authority does not override authoritative engineering sources/oracles/tests.
- Agent proposals remain advisory.
- Roadmap observed status must be re-grounded before use.
- Chain-local concurrency/custody and qualification rules remain intact.
- Merge authority and roadmap-write authority remain separate.
