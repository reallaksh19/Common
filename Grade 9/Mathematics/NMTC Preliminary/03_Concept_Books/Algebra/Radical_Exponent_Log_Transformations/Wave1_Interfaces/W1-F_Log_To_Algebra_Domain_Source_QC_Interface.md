# Issue #45 — Wave 1F Interface
## Log-to-algebra conversion & source/domain QC

`STATUS: W1_INTERFACE_COMPLETE`

`ROLE: INTERNAL_SUBTOPIC_INTERFACE`

This stream turns logarithmic surfaces into small algebra while preserving every condition that made the original logarithms meaningful.

## 1. CONCEPTS

- choose the repeated logarithmic object as the substitution variable;
- `t=log_b x` versus `u=sqrt(log_b x)`;
- carry substitution range such as `u>=0`;
- convert equal logs / related bases to algebraic power relations;
- restore argument/base constraints after logs disappear;
- reject algebraic branches invalid in the original log problem;
- separate learner error from source/key conflict.

## 2. PREREQUISITES

- log definition and real-domain restrictions;
- basic log laws derived from exponent laws;
- quadratic solving;
- positivity and substitution checking;
- source-integrity vocabulary from the NMTC authority layer.

## 3. RECOGNITION_CUES

| Visible cue | Structural recognition |
|---|---|
| repeated `log_b x` polynomially | set `t=log_b x` |
| repeated `sqrt(log_b x)` | set the whole object `u=sqrt(log_b x)` and record `u>=0` |
| equal logs with related bases | move to one base / exponent relation |
| logs disappear after conversion | original positivity conditions still survive |
| transformed algebra has multiple roots | filter through substitution range and original log domain |
| key conflicts with valid recomputation | stop and classify source status; do not force the key |

## 4. FIRST_MOVES

1. Write every original log-domain condition before substitution.
2. Circle the whole repeated object and use that as the variable.
3. Record the range inherited by the substitution (`u>=0`, `t` unrestricted if it is an ordinary log value, etc.).
4. Convert related-base log equalities to a power/algebra relation only after domain validity is established.
5. Map every algebraic solution back and test it in the original logarithmic statement.

## 5. INVARIANTS

- original argument positivity remains authoritative after logs are eliminated;
- the substitution variable represents the same repeated object at every occurrence;
- related-base log equalities encode exact power relations;
- only branches that map back to valid original variables survive;
- source disposition cannot be upgraded merely because a convenient repair is obvious.

## 6. REPRESENTATION_SWITCHES

- polynomial in `log_b x` -> polynomial in `t`;
- polynomial in `sqrt(log_b x)` -> polynomial in `u` with `u>=0`;
- `log_4 x=log_2 y` -> `(1/2)log_2 x=log_2 y` -> `x=y^2`, with `x,y>0`;
- transformed algebra -> original-variable map -> domain filter;
- printed statement / derived mathematics / supplied key -> separate source-QC records.

## 7. REVERSIBILITY_OR_DOMAIN_CONDITIONS

- every log argument must be positive;
- bases must satisfy `b>0`, `b!=1`;
- `u=sqrt(log_b x)` requires both `log_b x>=0` and `u>=0`; the implied condition on `x` depends on whether `b>1` or `0<b<1` and must be interpreted correctly when material;
- equality of valid same-base logs is equivalent to equality of arguments;
- algebraic roots obtained after substitution are candidates until mapped back through all inherited restrictions;
- source conflicts remain conflicts even when one likely correction is apparent.

## 8. DECISION_BOUNDARIES

`F-DB1 t=log_vs_u=sqrt(log)`  
Choose the whole repeated object; do not default to the innermost log.

`F-DB2 ALGEBRAIC_ROOT_vs_ORIGINAL_LOG_SOLUTION`  
A polynomial root is only a candidate until it maps back to a valid log argument.

`F-DB3 SAME_BASE_EQUALITY_vs_INVALID_ARGUMENT`  
You may equate arguments only after both logarithms are defined.

`F-DB4 CHANGE_BASE_USEFUL_vs_REFLEX`  
Change base when it exposes the relation, not as a ritual.

`F-DB5 LEARNER_ERROR_vs_SOURCE_CONFLICT`  
Recompute independently first; if mathematics and printed/key evidence disagree, preserve the conflict instead of editing the source silently.

## 9. MISCONCEPTION_TRAPS

- choosing `t=log_b x` when `sqrt(log_b x)` is the repeated object;
- forgetting `u>=0`;
- forgetting original argument positivity after conversion;
- equating log arguments before checking domains;
- accepting negative/zero original variables generated by algebra;
- changing a source sign or interpretation to match a provisional key;
- confusing a transformed polynomial multiplicity with distinct original solutions.

## 10. CONTRAST_PAIRS

### CP-F1 — two plausible substitutions
`log_2 x-5sqrt(log_2 x)+6=0`:
- `t=log_2 x` leaves `sqrt(t)`;
- `u=sqrt(log_2 x)` creates a quadratic directly.

### CP-F2 — algebra root vs domain-valid root
`log_2(x-1)+log_2(x-3)=3` gives algebraic roots `5,-1`; only `5` satisfies `x>3`.

### CP-F3 — valid equal logs vs undefined logs
`log_2 A=log_2 B` lets us infer `A=B` only when `A>0` and `B>0`.

### CP-F4 — calculation error vs source conflict
A student arithmetic error is repaired in the solution. A verified mismatch between printed source and key is recorded as source conflict and not silently rewritten.

- log system that converts to a quadratic relation with positivity filtering;
- combined log equation with one algebraic root outside the original argument domain;

### F-M3 — log system to algebra
