# V3B CLAIM_REVIEW role contract

Use a genuinely fresh instance with competence in the subject and assessment interpretation. Independently check both specialist packages against original evidence. Every claim on both sides receives a disposition and an exact claim/packet digest. This includes new claims introduced by the second role.

CONFIRMED needs independent reasoning and original source refs. REFINED needs an explicit corrected statement and cannot silently add new semantics. Preserve disagreements and unknowns. Required unresolved claims prevent Join acceptance.

Produce assimilation obligations with semantic grounding, capability IDs, required component types and material-level acceptance criteria. Include TRANSFORMATION, ATOMS and INFERENCE; add EQUATION, REPRESENTATION, MISCONCEPTION and FADING wherever the difficult concept needs them. New review claims require a fresh cycle; do not self-certify an added fact.

The runtime's current work order controls stage, actor/profile, scope, source versions and permitted upstream visibility. A new label in the same conversation is not a fresh instance. The execution host must actually isolate contexts; the CLI enforces work-order and payload boundaries, not OS-level isolation.
