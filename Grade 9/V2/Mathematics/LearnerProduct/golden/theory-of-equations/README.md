# Golden process fixture — Theory of Equations

This fixture exists to show future agents **how to execute the learner-product process**, not to provide content to copy into another topic.

## Do not copy the mathematics

Copy this sequence instead:

```text
bind exact upstream learner/core inputs
→ synthesize teaching buckets
→ materialize representation sequences
→ realize learner-conditioned Core1A teaching
→ map every Core2 question/hint back to taught content
→ preserve every Core2 source item
→ select governed challenge slots
→ generate from approved competitive archetypes
→ independently solve and scope-check each challenge
→ attach inline provenance to every question
→ author staged help
→ author Think it through
→ author Full working
→ author Quick check
→ render
→ visually preflight
→ final audit
```

## Expected Theory of Equations shape

The reference implementation demonstrated these concept groups:

1. roots → factors → equation construction;
2. coefficients ↔ root relations;
3. recovering two hidden roots using pair sum/product and an auxiliary quadratic;
4. symmetric expressions;
5. Newton sums / recurrence.

These groups are a golden example only. A new topic must synthesize its own buckets from governed Core1 capability/PCK/problem-family authority.

## What a conforming run must prove

- every required Core1 capability appears in exactly one Core1A bucket;
- learner state/treatment matches M-F exactly;
- each substantive bucket has a representation sequence or an explicit not-applicable reason;
- every Core2 source question is preserved exactly and remains attempt-first;
- every Core2 hint maps to taught Core1A content;
- challenge count/type follows the execution policy rather than ad-hoc author judgment;
- every generated challenge is independently solved and uses only taught/approved mathematics;
- every learner question carries its own `WHERE THIS QUESTION CAME FROM` box;
- generated competition-style questions disclose fresh/original status;
- learner pages use approved public labels and contain no internal pipeline vocabulary;
- render preflight and final audit pass.

See `EXPECTED_STRUCTURE.json` for machine-readable expectations.
