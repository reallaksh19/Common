# Unified A-layer content-first pagination

The unified four-Core custody/render path treats page count as an output, not a quality target.

For Core1A and Core2A, the renderer must preserve governed answer-visibility boundaries while placing independent semantic blocks into available space before forcing a new page. It may repeat exact governed question context on an answer/check surface, but it may not invent Chemistry or filler to increase density.

The current learner-render policy establishes a physical sparse-fragment falsifier for unified A products. The machine check uses the renderer's recorded physical draw operations, excludes the footer, exempts the cover page, and rejects a non-cover page whose active vertical span is below the policy floor. This is intentionally separate from page-count optimization.

Core1B and Core2B retain their governed static reconstruction/transfer pagination and are not rewritten by this A-layer rule.

The pure density predicate is dependency-free so Learning Blueprint tests can falsify pagination policy without importing PDF rendering libraries. The actual product preflight independently parses the generated PDF and combines geometry, font, learner-surface and content-first checks.
