# Physics Core2A v7 — CCU-governed Problem TTUs + LAU fit

Core2A is declarative-dominant expert problem learning from the exact legal pool. V7 adds CCU question custody and LAU v2 fit receipts.

## Authority path

`frozen Core2 custody → CCU question/answer/source receipts → CDAU purpose/differentiation → LAU → Problem TTU → Core2A`

## Question custody

Every Core2A exemplar must preserve:

- stable question ID;
- source class and visible source label;
- original source question number when source-derived;
- legal-pool lineage/digest;
- problem family/bucket/capabilities;
- canonical answer/solution;
- example fingerprint;
- answer status.

A source item with unresolved prompt or answer is `HELD` and cannot enter production Core2A. Author-created design-pilot items must be visibly labelled nonproduction and do not expand the legal pool.

## Selection and learner fit

LAU v2 requires exactly one selection basis: capability-specific `KNOWLEDGE_PERCENT` with provenance/confidence/recency, or explicit `OWNER_OVERRIDE` when usable knowledge evidence is unavailable. No silent default.

Each selected item receives a task-demand vector and fit receipt. The fit label is routing guidance, not a psychometric or mastery claim.

## Problem TTU

Representative worked exemplars expose:

`question → setup extraction → representation/model selection → mapped givens → intermediate working → result → independent verification`

Core2A should not solve every legal item by default.

## Cross-Core lineage

Core2A exemplars must be fingerprinted so Core2B can use a declared `FADING_ANCHOR`, `STRUCTURAL_SIBLING`, or `FAR_TRANSFER_SIBLING`. Exact replay is not fresh transfer.

## Release

Production Core2A requires `G_CUSTODY_COVERAGE`, exact legal-pool custody, `G_PURPOSE`, `G_DIFFERENTIATION`, `G_FIT`, `G_TTU`, and source/answer resolution.
