# Physics Core1A Technical Publication Spec v5 — CCU → CDAU → SDU → Concept TTU

Core1A is declarative-dominant deep conceptual teaching. V5 adds **CCU custody** ahead of CDAU/SDU so authored depth cannot silently omit canonical equations/data/representations and every learner-facing example/question remains sourced and resolved.

## Authority path

`ground truth / validated Core chain → canonical domain registry → CCU → CDAU → SDU → Concept TTU → Core1A publication`

## CCU input is mandatory

Before manuscript/publication, Core1A must consume a CCU coverage receipt proving:

- every applicable canonical asset has an explicit disposition;
- every `REQUIRED` asset has a realization reference;
- every `HELD` asset has a reason rather than disappearing;
- every learner-facing question/example has stable question ID, source class, visible source label and canonical answer/solution/derivation/diagram/rubric;
- frozen source numbering is retained;
- worked examples have example fingerprints and cross-Core duplication classification.

Author-created examples must be visibly labelled `AUTHOR_CREATED`; they may not impersonate frozen source questions.

## Difficulty

Core1A uses the SDU v2 intrinsic difficulty receipt, never student knowledge percentage. Difficulty is supported by the 0–3 evidence profile and critical-bottleneck record. Easy/Medium/Hard retain soft maximum depth envelopes of ~10/~20/~30 pages, not quotas.

## Concept TTU

Every major Medium/Hard inferential jump must close:

`semantic target → canonical expert state → technical representation → equation/relation binding → reasoning chain → conclusion → independent verification`

The TTU also authors legitimate downstream Core1B transformations. A diagram/equation without reasoning binding is not closure.

## Cross-Core duplication

Fundamental equations may recur as declared semantic reuse. Exact numeric worked examples, complete diagrams, explanatory paragraphs and solution paths may not silently mirror Core1B. CCU similarity/fingerprint receipts must classify the relationship.

## Release

Core1A requires `G_DOMAIN`, `G_CUSTODY_COVERAGE`, `G_PURPOSE`, `G_DIFFERENTIATION`, `G_DIFFICULTY`, `G_TTU` and `G_PUBLICATION`.
