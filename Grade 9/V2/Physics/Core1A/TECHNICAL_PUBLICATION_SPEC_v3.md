# Physics Core1A Technical Publication Spec v3 — TTU v2 canonical teaching

Core1A remains declarative-dominant. Its major inferential jumps and problem families are authored as **TTU v2 objects**, not as independent pages/diagrams.

## Core1A realization

Core1A normally renders the TTU's **canonical completed state**:

`setup → complete representation → governing relation → representation/equation mapping → intermediate working → result → verification`

The underlying TTU must already contain the downstream reconstruction contract even when Core1A does not render it.

This means Core1B may remove or hide only semantically identified elements that already exist in the Core1A-authorized TTU. Core1B may not invent a different diagram, relation, missing step or canonical answer.

## Required TTU v2 fields

For every major Hard-bucket inferential jump/problem family:

- authority binding;
- capability / learning-atom target;
- physical setup and model conditions;
- canonical representation elements with stable IDs;
- representation-to-relation bindings;
- governing relation(s);
- intermediate technical working;
- canonical result/conclusion;
- preauthored reconstruction omissions;
- fixed help mapped to omitted element IDs;
- independent verification rule(s).

## Important distinction

Core1A may show the complete reference state because its dominant purpose is explanation. But a complete diagram by itself is not a TTU. The TTU exists only when the corresponding learner-reconstruction and verification state is also defined in the underlying contract.
