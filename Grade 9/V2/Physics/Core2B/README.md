# Physics Core2B — evidence-gated transfer runtime

Core2B selects the next learner experience from an exact Core2A legal pool. It has no authority to legalize, rewrite or generate transfer items.

## Two independent gates

1. **Core2A legality:** exact product ref + digest and exact item ID.
2. **Learner evidence:** every capability required by the selected Core2A item must meet the item's evidence floor.

There is no session-wide mastery flag. Capability ceilings are derived from a bound Core1B independent-release receipt plus append-only observed Core2B transfer events.

## Transfer demand

`T0..T8` may be displayed as a convenient ordering label, but authorization is multidimensional:

- structural distance;
- representation change;
- model discrimination;
- multi-step bridge;
- synthesis;
- competitive mixing.

Discrimination and synthesis are independent demands, not consecutive mastery states. Representation transfer requires matching successful observed representation evidence.

## Error and repair

A wrong answer is not a diagnosis. Automatic classification produces an explicit `HYPOTHESIS`; repair routing uses the smallest explanatory prerequisite set and returns to the original Core2A item. Repair requests cannot mutate Core1A or Core2A authority.

## Retrieval

Retrieval state is append-only. An attempted representation is added to successful representation evidence only after a correct observed attempt; an incorrect exposure cannot silently become representation mastery.
