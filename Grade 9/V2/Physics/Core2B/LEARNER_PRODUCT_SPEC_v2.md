# Physics Core2B v2 — Generative Transfer Coach

## Learner-product purpose

Core2B is a **self-guided generative transfer product**. It asks:

> Can the learner recognize, select and transfer the capability when the surface changes?

The learner should meet the problem **before** being told the model. Core2B must preserve productive struggle without abandoning the learner.

## Canonical transfer episode

```text
UNFAMILIAR QUESTION
-> FIRST MOVE ATTEMPT
-> SOLUTION ATTEMPT
-> H1 NOTICE
-> H2 REPRESENT
-> H3 START
-> TRY AGAIN
-> CHECK AFTER ATTEMPT
-> WHAT STAYED THE SAME?
-> WHAT CHANGED?
-> repair route
```

### Hint semantics

- **H1 NOTICE** — point to the event/invariant/clue; do not give a formula.
- **H2 REPRESENT** — prompt a useful diagram, graph, table, event line, component model or symbolic structure.
- **H3 START** — provide the first executable conceptual/mathematical move, but not the completed solution.
- **FULL SOLUTION** — available after an attempt path; it is not independent-transfer evidence.

## What Core2B must vary

Difficulty is not a single harder/easier scalar. Transfer challenges may vary independently by:

- structural distance;
- representation change;
- model discrimination;
- multi-step bridge;
- synthesis;
- competitive mixing.

`T0…T8` may remain display/order vocabulary only.

## Self-guided solution block

Every challenge needs a post-attempt resolution with:

1. recognition — what hidden structure is present?
2. representation — how should it be shown?
3. model selection — why this model and not a competitor?
4. full working;
5. physical/limiting/dimensional check where relevant;
6. transfer statement — what stayed invariant?
7. variation statement — what surface/target changed?
8. repair pointer for likely failure modes.

## Repair behavior

A wrong answer is an **error hypothesis**, not a diagnosis. Repair must target the smallest explanatory prerequisite in Core1B. After repair, verify learning with a different legal Core2A item rather than only replaying the identical worked answer.

## Runtime authority remains unchanged

- exact Core2A legal-pool ref + digest and exact item ID remain mandatory;
- Core2B may not create or legalize transfer items;
- capability evidence is per-capability, not a session-wide mastery flag;
- incorrect/full-solution exposure cannot count as representation mastery;
- only successful sufficiently low-hint observed transfer may advance robustness.
