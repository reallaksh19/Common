# Physics Core1B v6 — Generative Reconstruction of Technical Teaching Units

## Purpose

Core1B is a self-guided generative-dominant learner product.

> Can the learner reconstruct the fragile technical structure taught in Core1A, rather than merely explain it in prose?

Core1B is not a prose worksheet and not a second declarative copy of Core1A.

## Fragile checkpoint rule

For every fragile checkpoint, identify the technical object an expert would naturally construct or inspect:

- vector triangle;
- component map;
- free-body diagram;
- trajectory/graph;
- event line;
- geometry construction;
- equation map;
- signed variable table;
- frame/axis diagram.

When that object is material to the skill, the learner must reconstruct, complete, label, compare, derive from, or use it.

## Reconstructable TTU

A substantive Core1B checkpoint should use:

```text
INCOMPLETE PHYSICAL SETUP / REPRESENTATION
→ LEARNER COMPLETES OR SELECTS
→ LEARNER STATES GOVERNING RELATION / FIRST MOVE
→ LEARNER WORKING
→ OPTIONAL PROGRESSIVE HELP
→ FULL TECHNICAL CHECK
→ VERIFICATION
→ SMALLEST REPAIR
```

The local check must show the technical bridge, not only the final number.

## What does not count

The following do not satisfy a Hard Core1B technical checkpoint:

- prose question + blank lines when a technical representation is central;
- generic cards or decorative diagrams;
- a fully solved diagram that leaves nothing for the learner to reconstruct;
- an equation prompt with no link to the physical setup;
- a final numeric answer without component/algebra/representation working.

## Technical density by problem family

For each major problem family, include at least one substantial reconstruction task containing, when material:

1. setup extraction;
2. genuine Physics representation;
3. governing relation;
4. numeric/symbolic manipulation;
5. physical/sign/limit/model check.

Core1B remains selective: it does not inherit Core1A's page count.

## Hint grammar

H1/H2/H3 are reserved for tasks where the learner can otherwise become stranded.

- **H1 NOTICE** — point to the event/invariant/frame mismatch;
- **H2 REPRESENT** — cue the needed diagram/graph/component structure;
- **H3 START** — give the first executable relation or construction.

Representation completion tasks may instead use:

`INCOMPLETE REPRESENTATION → LEARNER COMPLETES → CHECK → EXPLAIN KEY FEATURE`

## Layout and figure semantics

A figure counts only if it encodes Physics structure used in the reasoning. Generic A/B/C cards do not count as technical figures.

Learner-facing incomplete figures must be legible and leave purposeful space to complete the representation. Avoid oversized empty axes, microscopic labels, and rasterized equation text.

Figure and working remain adjacent.

## Evidence boundary

Technical richness does not change authority:

- Core1B cannot author new Physics semantics;
- reading the full check is teaching, not independence evidence;
- `INDEPENDENT` requires observed sufficiently low-hint successful learner evidence;
- Core1B cannot legalize transfer.
