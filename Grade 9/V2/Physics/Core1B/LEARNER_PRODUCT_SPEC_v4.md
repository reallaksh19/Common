# Physics Core1B v4 — Generative Concept Reconstruction

## Learner-product purpose

Core1B is a **self-guided generative-dominant teaching product**.

> Can the learner reconstruct, explain, represent and independently use the fragile parts of what Core1A taught?

Core1B is not a chatbot transcript, not minimally guided discovery, and not a second declarative copy of Core1A.

## Scope control

Core1B is always built against the same stable subtopic/SBA bucket and the same shared bucket learning model as Core1A.

Student knowledge percentage does **not** control authored Core1B depth.

However, Core1B does **not** inherit Core1A's page budget.

It inherits:

- hidden invariants;
- fragile inferential jumps;
- material misconceptions;
- problem families;
- representations needed for reconstruction;
- source/Core2 boundaries.

Its page count is derived from the smallest set of generative episodes needed to exercise those fragile points.

A Hard 28-page Core1A may legitimately have an 11-page Core1B. Symmetry is not a quality criterion.

See `../Blueprint/policy/core1ab-bucket-authoring.v2.json`.

## Dominant mode, not exclusive content

Core1B is **generative-dominant**.

It may still include:

- a short explanation after an attempt;
- a worked reconstruction after failure;
- targeted reteaching of the smallest broken bridge;
- a compact diagram or model answer.

It must not become a question-only worksheet.

## Required coverage

Core1B should contain at least one meaningful generative checkpoint for:

1. every fragile inferential jump;
2. every material misconception that can corrupt later reasoning;
3. every distinct problem family that needs independent recognition;
4. mixed/retrieval discrimination when multiple families can be confused.

It does **not** need to reproduce every Core1A explanation, derivation or diagram.

## Task grammars

Choose the smallest grammar that fits the task.

### Micro prediction / explanation

```text
PROMPT
→ ATTEMPT
→ MODEL RESPONSE / EXPLANATION
```

### Representation task

```text
DRAW / COMPLETE / TRANSLATE
→ CHECK REPRESENTATION
→ EXPLAIN THE KEY FEATURE
```

### Concept reconstruction

```text
OPEN PROMPT
→ ATTEMPT
→ OPTIONAL CLUE
→ CONCEPTUAL CHECK
```

### Substantive problem or fragile first move

```text
QUESTION
→ ATTEMPT
→ H1 NOTICE
→ H2 REPRESENT
→ H3 START
→ TRY AGAIN
→ FULL CHECK
→ REPAIR ROUTE
```

### Mixed retrieval

```text
UNLABELED TASK
→ ATTEMPT
→ COMPACT CHECK
→ IDENTIFY THE FAMILY / INVARIANT
```

## Hint-ladder rule

`H1 NOTICE → H2 REPRESENT → H3 START` is the standard progressive rescue ladder for substantive tasks.

It is **not mandatory for every open-ended prompt**.

- **H1 NOTICE** — point to the event, invariant or clue; no formula dump.
- **H2 REPRESENT** — prompt a useful diagram, graph, table, event line, component split or symbolic structure.
- **H3 START** — give the first executable conceptual/mathematical move, not the completed solution.

Every open-ended task still requires a local resolution on the same page or immediately following.

## Preferred instructional rhythm

A coherent Core1B product usually looks like:

`RECONSTRUCT → REPRESENT → TRY A FAMILY → OPTIONAL RESCUE → CHECK → NEXT FRAGILE POINT → MIXED RETRIEVAL`

Do not interrogate the learner after every sentence of Core1A.

## Repair behavior

A failed task should point to the smallest explanatory gap, for example:

- frame naming;
- sign convention;
- event identification;
- graph meaning;
- first-move selection;
- one specific problem-family routine.

Repair should not send the learner back to reread an entire chapter unless the failure genuinely spans the whole chapter.

## Visual policy

Visual quantity is not a target.

Use a representation when it materially helps the learner reconstruct a fragile jump.

A figure may serve one or more functions:

`REPRESENT | EXPLAIN | COMPARE | PREDICT | DERIVE | CHECK`

Decorative visuals do not count.

## Evidence boundary

- exact Core1A authority ref + digest remains mandatory;
- Core1B may not author new Physics semantics;
- teaching/readiness configuration is not mastery evidence;
- full-solution exposure is teaching, not independent mastery evidence;
- `INDEPENDENT` still requires observed sufficiently low-hint learner evidence;
- Core1B cannot legalize Core2A/Core2B transfer.

## Benchmark-derived rule

Mature bucket publications show the preferred rhythm:

`IDEA → REPRESENTATION → WORKED EXAMPLE → PROBLEM FAMILY → ATTEMPT → OPTIONAL HINTS → ANSWER → NEXT FAMILY`

Core1B should extract and strengthen the **generative checkpoints** from that rhythm rather than recreate the entire declarative book.
