# Physics Core1B v8 — SDU Concept-TTU reconstruction

Core1B asks whether the learner can reconstruct and independently use conceptual structure already authorized upstream. It is the generative-dominant realization of the same SDU bucket used by Core1A.

## Authority path

`validated domain → CDAU → SDU → Concept TTU → Core1B`

Core1B has no semantic teaching authority. It may transform an authorized Concept TTU but may not create a new law, model condition, canonical answer or source interpretation.

## Same difficulty envelope, independently derived length

Core1B shares the bucket's `EASY | MEDIUM | HARD` maximum depth envelope (`~10 / ~20 / ~30`) with Core1A. This is capacity, not a quota or symmetry rule. Actual Core1B length is independently derived from fragile inferential jumps, misconception pressure, representation translations, model-selection checkpoints and retrieval needs.

## Reconstruction is broader than blanks

A learner-facing Concept TTU must use one or more meaningful transformations selected from:

`PREDICTION | COMPLETION | GENERATION | SELECTION | DISCRIMINATION | DIAGNOSIS | DERIVATION_CONNECTION | VERIFICATION`

A blank is optional. What is mandatory is a change in reasoning state and an observable learner product.

Examples include:

- generate the frame/vector diagram from a verbal setup;
- select the correct model before calculation;
- discriminate two plausible models and explain the rejected one;
- diagnose a technically plausible wrong solution;
- derive the symbolic connection between representation and equation;
- complete a canonical partial state using semantically identified elements.

Cosmetic blanks, arbitrary missing numbers and copy-the-nearby-answer tasks do not count.

## Tutor dialogue / self-help contract

The learner receives an initial attempt before canonical reveal. Help is preauthored, bounded and target-driven. Available functions are:

`NOTICE | REPRESENT | EXPLAIN | CONNECT | START | CONTRAST | REPAIR`

Not every task uses every function. For substantive tasks, help must rescue the specific unresolved reasoning structure without injecting new semantics downstream.

## Canonical reveal and verification

After attempt, the learner can access the canonical expert state and compare reasoning, not just the final answer. Full solution exposure is teaching evidence, never mastery evidence.

At least one independent verification rule should be usable before reveal when technically possible: inverse relation, substitution-back, limiting case, units/dimensions, sign/direction, graph behavior, boundary condition, alternate representation or model-validity check.

## Cross-Core differentiation

Core1B may semantically reuse the same concept/equation as Core1A but must not silently mirror the same numeric example, complete diagram, prose explanation and solution path. Reuse of an exact anchor requires explicit CDAU lineage such as `FADING_ANCHOR`; otherwise a transformed or fresh example fingerprint is required.

## Hard-bucket rule

A Hard Core1B is noncompliant if it is mostly prose prompts while the capability naturally requires vectors, graphs, component constructions, event lines, free-body diagrams, symbolic relations or other technical representations. It should include multiple high-value reconstruction modes rather than a pile of micro blanks.
