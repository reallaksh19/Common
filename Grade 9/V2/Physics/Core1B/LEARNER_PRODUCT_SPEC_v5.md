# Physics Core1B v5 — Generative Technical Reconstruction

## Purpose

Core1B remains a self-guided generative-dominant learner product.

> Can the learner reconstruct, represent, explain and independently use the fragile technical structure taught in Core1A?

Core1B is not a prose worksheet and not a second declarative copy of Core1A.

## Core rule for Hard buckets

A Hard Core1B must visibly contain the technical forms required by the capability.

Prose prompts and blank answer lines are insufficient when the concept depends on:

- vector diagrams;
- component splits;
- free-body diagrams;
- graphs;
- event timelines;
- geometric constructions;
- symbolic transformations;
- equations or derivations.

For each fragile checkpoint, ask what technical representation an expert would actually construct. The learner must reconstruct, complete, label, compare or use that representation.

Examples:

- complete a velocity triangle rather than merely explain relative velocity in words;
- fill missing component equations rather than only state the idea;
- sketch two frame-dependent trajectories and write their equations;
- complete an event timeline before using kinematics;
- label forces on a free-body diagram before selecting Newton's law;
- derive or rearrange the key relation when algebraic structure is part of the skill.

## Technical-density requirement

Hard Core1B should contain, when material:

1. at least one formal symbolic relation for each major model family;
2. learner-facing diagrams/graphs for fragile representational jumps;
3. at least one numeric or algebraic reconstruction task per major problem family;
4. visible intermediate technical working in the check/solution;
5. a physical, dimensional, sign or limiting-case check where applicable.

There is no image quota. One adequate figure may support several tasks. Decorative figures do not count.

## Relationship to Core1A

Core1B inherits:

- hidden invariants;
- fragile inferential jumps;
- material misconceptions;
- problem families;
- technical representations needed for reconstruction;
- source/Core2 boundaries.

It does not inherit Core1A's page budget or repeat all of Core1A's exposition.

## Task grammar

Use the smallest self-help pattern that preserves technical reconstruction.

### Representation reconstruction

`INCOMPLETE DIAGRAM / GRAPH / TABLE / EQUATION → LEARNER COMPLETES → TECHNICAL CHECK → EXPLAIN KEY FEATURE`

### Substantive problem

`QUESTION → ATTEMPT → H1 NOTICE → H2 REPRESENT → H3 START → RETRY → FULL TECHNICAL CHECK → REPAIR`

### Micro concept check

`PREDICT / EXPLAIN → ATTEMPT → COMPACT MODEL RESPONSE`

### Mixed retrieval

`UNLABELED TECHNICAL TASK → ATTEMPT → CHECK → IDENTIFY FAMILY / INVARIANT`

## Local resolution

Every open task has a local resolution. For numerical/symbolic tasks, the resolution should normally include:

- the representation/model selected;
- intermediate equations or vector/component steps;
- final result;
- physical/sign/limit check when useful.

A final number without the reasoning is not sufficient self-help.

## Layout integrity

Core1B figures must be isolated layout blocks or otherwise collision-validated. Production release requires rendered-page inspection with no text/figure overlap.

See:

- `../Blueprint/policy/technical-density-and-figure-contract.v1.json`

## Evidence boundary

Technical richness does not alter authority:

- Core1B cannot author new Physics semantics;
- full-solution exposure is teaching, not independence evidence;
- `INDEPENDENT` still requires successful sufficiently low-hint observed learner evidence;
- Core1B cannot legalize Core2 transfer.
