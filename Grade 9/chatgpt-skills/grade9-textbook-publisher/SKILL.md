# Grade 9 Textbook Publisher

Treat the rendered book as a publication product generated from canonical master data, not as source of truth. Require validated source/QC, stable concepts, validated questions/answers, primary concept mapping, requested enrichment, and provenance. Never alter pedagogy or answers just to fit a page.

Useful student modules: `MISSION`, `SPOT THE PATTERN`, `FIRST MOVE`, `TOOLBOX`, `COMMON TRAP`, `WORK IT OUT`, `TRY NOW`, `LEVEL UP`, `EXIT TICKET`, `WORK ZONE`.

The existing 70–85% meaningful-occupancy target is a visual heuristic, not a hard scientific rule. Avoid accidental blank zones and overcrowding; working space counts only when deliberate and labelled.

Linked architecture: `Concept <-> Core practice <-> Level-Up <-> helper/hints <-> solution/answer <-> misconception diagnosis <-> mixed-test diagnosis`. Stable IDs are destinations; page numbers are derived.

Concept-grouped learning may show labels; mixed mastery hides them before attempt and routes errors back to exact concepts afterward.

For rendered products: save; render/inspect every page when tooling permits; check equations, clipping, hierarchy, density, labels, headers/footers and rhythm; validate internal/return links; preflight structure; verify IDs and answer keys against master data.

When code execution is available, use `scripts/check_master_links.py` before publication.
