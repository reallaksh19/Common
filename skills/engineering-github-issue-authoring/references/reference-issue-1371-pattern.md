# Reference Pattern — Advanced_Analysis issue #1371

Reference:

```text
reallaksh19/Advanced_Analysis#1371
[LAFEA.3/.4] Close Model → Mesh → Analyse → Output with frozen benchmark and anti-drift gates
```

This is a **quality/depth reference**, not a generic engineering authority source.

## What to emulate

The issue establishes an unusually complete implementation work order by combining:

1. a concrete mission and product path;
2. creation-time repository SHA and a mandatory re-ground warning;
3. registered production authority and explicit current limitations;
4. a Definition of Done organized by real workflow states;
5. a phased PR-sized execution strategy;
6. a takeover/overlap gate before mutation;
7. exact input-source authority and regression fixture locations;
8. live API/function examples and minimum implementation skeletons;
9. exact PASS conditions for mesh/analyse/output state;
10. independent/frozen benchmark definitions separated from product regressions;
11. anti-circularity rules for expected values/tolerances;
12. explicit exclusions and capability boundaries;
13. negative/anti-drift expectations;
14. a validation matrix with `PASS/FAIL/NOT_RUN` truth;
15. an implementation takeover qualification appendix.

## Reference question pattern

Its Appendix A asks five implementation questions around:

```text
A1 production trace
A2 current failure isolation
A3 authority/invariant
A4 independent validation
A5 smallest next patch
```

The existing A1 requires the incoming agent to trace both LAFEA.3 and LAFEA.4 from source normalization through result presentation using actual live functions/files.

A2 asks for the first incomplete or contradictory user-visible boundary using file/DOM/state evidence.

A3 asks how stale source/mesh is blocked and which parent hashes/projections must agree, plus a falsifier.

A4 distinguishes independent/frozen LAFEA.3 numerical oracles from product regressions and asks for a valid LAFEA.4 oracle if missing.

A5 asks for the smallest coherent first PR/commit, exact changed/protected files, failing evidence before, PASS after, and the main hypothesis/falsifier.

## What the new skill deliberately strengthens

The reference questions are strong repository/authority questions, but a numerical engineering issue should go further when concrete engineering inputs are available.

New skill requirement:

```text
>= 2 genuine hand-calculation questions for numerical engineering
```

Examples:

```text
actual T6/Q8 Jacobian/integration reconstruction
actual statics equilibrium and moment transport
actual shell/continuum analytical benchmark calculation
actual WRC/local-axis reconstruction
```

The implementation candidate must establish the independent result **before** using production output for comparison.


When a user says `similar to #1371`, copy the **discipline and completeness**, then rebuild all technical facts from the target repository.
