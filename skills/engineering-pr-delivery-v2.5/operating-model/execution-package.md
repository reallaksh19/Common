# Execution package (EP)

An EP is a forward-looking executable contract derived from one roadmap frontier node.

Required content: immutable identity; exact roadmap revision/objective/phase/work-package; observable outcome; context capsule; repository discovery; durable inputs/benchmarks; allowed/prohibited scope with reasons; anti-drift/staleness; stepwise plan; quality blueprints; weighted acceptance; classified validation; true stop conditions; exact report contract; checkpoint duties; successor duties.

The EP fails if a new agent needs chat to resolve a material instruction. It identifies expected branch/base-state semantics. `scope.allowed` grants bounded change authority. `scope.prohibited` records protected domains and why. If acceptance requires prohibited changes, the EP becomes stale or requires authority escalation; scope does not silently expand.
