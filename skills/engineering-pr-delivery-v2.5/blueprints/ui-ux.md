# UI/UX blueprint

Evaluate user goal, happy path, partial input, invalid input, empty/loading states, error recovery, keyboard/focus behavior, accessibility, responsive behavior, authority visibility, performance and end-to-end journey.

Every user-visible warning/restriction/error should answer: What happened? Why does it matter? What should the user do? What can the user still safely do?

Prefer plain language. Do not leak relay/qualification/gate/blocker jargon into product UI without user-facing meaning. Distinguish missing information, quality recommendation, evidence failure, user decision and actual inability to continue safely.
