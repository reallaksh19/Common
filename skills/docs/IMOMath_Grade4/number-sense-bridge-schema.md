# Grade 3 -> Grade 4 Number Sense / Pre-IMO Schema

## Purpose

This document defines two related Numbers / Number Sense modes:

1. a **Grade 3 -> Grade 4 bridge**, where tight concept clusters help the learner climb into current-class content; and
2. a **Grade 4 pre-IMO progression**, where the learner must use the same underlying Number Sense structures across deliberately different question archetypes.

The key design rule is:

> Preserve conceptual continuity, but do not teach transfer by repeating the same question template with different numbers.

Round 1 teaches and strengthens the thinking tools. Round 2 tests whether the learner can recognize and select those tools when the surface form changes.

## Curriculum boundary

For the SOF Class 4 Number Sense / Large Numbers domain, the relevant content includes:

- numerals and number names;
- place value and face value;
- expanded and regrouped representations;
- comparing and ordering;
- forming numbers;
- rounding;
- even / odd structure;
- Roman numerals.

Factors and Multiples belongs to a separate Class 4 topic family and should not be silently mixed into a Number Sense-only set.

## 1. Two Round 1 modes

### Mode A - bridge ladder

Use when the learner is still moving from secure Grade 3 content into Grade 4 content.

A cluster may use:

```text
familiar prerequisite
-> direct Grade 4 extension
-> one extra reasoning / application demand
```

Example:

```text
compare 4-digit numbers
-> compare close 5-digit numbers
-> rank four close 5-digit numbers
```

Neighboring items may look similar because the immediate goal is controlled extension.

### Mode B - Grade 4 pre-IMO concept-building progression

Use when basic Grade 4 Number Sense is present and the goal is pre-IMO reasoning.

Do **not** create ten near-copies of midpoint, clue-number, or digit-formation questions.

Instead, choose a progression of different archetypes that repeatedly exercise a compact set of underlying structures:

```text
place-value magnitude
number decomposition / regrouping
comparison constraints
number-line distance / equidistance
boundary continuity
rounding intervals
representation conversion
parity structure
balance / equality
systematic enumeration
constraint organization
```

The questions should look different enough that the child must reconstruct the idea rather than recognize the worksheet pattern.

## 2. Pre-IMO archetype families

### NS-PV - Place-value magnitude

Possible archetypes:

- difference between place value and face value;
- change in total number when one digit changes;
- compare the contribution of two digits;
- infer a missing digit from a place-value condition.

Atomic skills:

```text
identify_place
identify_place_value
distinguish_face_and_place_value
measure_digit_contribution
reason_about_place_value_change
```

### NS-REG - Flexible decomposition and regrouping

Possible archetypes:

- choose a nonstandard expanded form;
- compose from 42 thousands + 15 hundreds + ...;
- exchange thousands / hundreds while preserving total;
- detect a regrouping error.

Atomic skills:

```text
compose_number
decompose_number
regroup_place_value_units
recognize_equivalent_representation
```

### NS-CMP - Comparison as constraint

Possible archetypes:

- greatest / smallest digit that makes an inequality true;
- identify first place that decides comparison;
- order close values;
- second-highest / second-smallest.

Atomic skills:

```text
compare_left_to_right
identify_deciding_place
solve_missing_digit_inequality
order_multiple_numbers
```

### NS-DST - Distance, midpoint and equal spacing

The conceptual target is **equidistance and interval structure**, not memorizing a midpoint formula.

Possible archetypes:

- closest number to a landmark;
- equal markers between two endpoints;
- find a missing equally spaced marker;
- given the middle, recover an endpoint;
- predecessor / successor symmetry.

Atomic skills:

```text
measure_number_line_distance
recognize_equidistance
split_interval_equally
reason_across_place_value_boundary
```

### NS-BND - Boundary continuity

Possible archetypes:

- predecessor / successor around 9,999 / 10,000 or 99,999 / 1,00,000;
- nth number after a boundary-crossing start;
- compare values on opposite sides of a digit-length boundary.

Atomic skills:

```text
successor
predecessor
cross_number_boundary
ordinal_count_from_value
```

### NS-RND - Rounding as an interval

Do not teach rounding only as `look right -> round up/down`.

Possible archetypes:

- ordinary rounding;
- smallest / greatest number that rounds to a target;
- count which listed values round to a target;
- identify a value that cannot / could round to a target;
- reason about the full rounding band.

Atomic skills:

```text
identify_rounding_place
round_number
construct_rounding_interval
reason_from_rounded_value
identify_interval_endpoint
```

### NS-ROM - Roman numeral reasoning

Possible archetypes:

- decode;
- encode;
- validate a numeral;
- decode -> operate -> encode.

Atomic skills:

```text
roman_symbol_value
roman_additive_form
roman_subtractive_form
convert_roman_to_hindu_arabic
convert_hindu_arabic_to_roman
validate_roman_numeral
operate_across_representations
```

### NS-PAR - Parity structure

Possible archetypes:

- identify which sum / difference must be odd or even without full calculation;
- choose a final digit under an odd/even condition;
- combine parity with digit formation.

Atomic skills:

```text
recognize_even_odd
use_parity_rules
use_ones_digit_as_sufficient_information
apply_parity_constraint
```

### NS-BAL - Equality and balance

Possible archetypes:

- same number added to one quantity and subtracted from another until equal;
- predecessor and successor sum;
- two values moving equally toward a middle point.

Preferred representation:

```text
bar_balance
number_line_symmetry
```

Atomic skills:

```text
interpret_equality_as_balance
split_difference_equally
recognize_symmetric_change
```

### NS-ENUM - Systematic enumeration under constraints

Possible archetypes:

- how many numbers can be formed under boundary + parity rules;
- count candidates rather than find a single candidate;
- organize cases by leading digit or final digit;
- eliminate impossible branches.

Atomic skills:

```text
apply_constraints
partition_cases
count_valid_cases
avoid_duplicate_cases
systematic_enumeration
```

### NS-CLU - Constraint / clue organization

This is broader than one `I am a number` template.

Possible archetypes:

- construct a number from clues;
- inspect answer choices and identify which satisfies all clues;
- fill digit slots from direct + relational clues;
- combine digit sum, place relationship, parity, and boundary;
- optimize only after constraints are satisfied.

Preferred representations:

```text
digit_slots
clue_board
possibility_table
elimination_marks
```

Atomic skills:

```text
externalize_clues
map_clue_to_place
apply_relational_constraint
use_digit_sum
coordinate_multiple_constraints
eliminate_invalid_candidates
optimize_after_constraints
```

## 3. Round 1 generation contract

### Bridge mode

Use tight 3-rung clusters where appropriate.

### Pre-IMO mode

Use a curated sequence of varied archetypes.

Rules:

- do not repeat the same surface template merely with larger numbers;
- do not make all ten questions `find the number`, `find the midpoint`, or `make greatest/smallest`;
- preserve a manageable conceptual backbone across the set;
- introduce one unfamiliar reasoning demand at a time overall, even when the question form changes;
- label the thinking family in child-friendly language if that helps learning;
- allow the child to draw their own number line, place-value alignment, clue boxes, list, or table;
- initial attempts remain unsupported;
- if a question is difficult, convert that exact question into a partial worked example.

A strong 10-item pre-IMO Round 1 may sample:

```text
1  place-value magnitude / face-vs-place
2  equivalent regrouping
3  missing-digit inequality
4  distance to a landmark
5  predecessor/successor boundary
6  rounding interval
7  Roman numeral operation
8  parity without full computation
9  equality / balance
10 systematic enumeration under constraints
```

This is an example architecture, not a mandatory fixed list.

## 4. Question-to-example behavior

When a Round 1 question is difficult:

```text
original question
-> LET'S WORK THIS ONE OUT TOGETHER
-> same question becomes a partial worked example
-> optional small diagnostic check only when needed
-> expose one useful representation / structure
-> child completes one key step
-> TRY ONE: fresh close question
```

The original is then `instructionally_exposed: true` and is burned for independent evidence.

The close `TRY ONE` should preserve the atomic idea but may change the surface form slightly. It is a hand-back step, not the final transfer test.

## 5. Round 2 - deliberately interleaved transfer

Round 2 is not `Round 1 with the headings removed` and not a random grab bag.

It should be deliberately interleaved so the child must decide:

> What kind of structure is hidden here, and what tool could help me?

Rules:

- remove concept labels;
- change the surface form relative to Round 1;
- mix archetype families;
- avoid placing obvious near-copies beside one another;
- do not supply instructional representations;
- allow the learner to create their own representation;
- use plausible distractors tied to real misconceptions;
- keep most items in Grade 4 core / pre-IMO demand;
- reserve full Achievers complexity for a later stage unless explicitly requested.

Examples of useful transformations from Round 1 to Round 2:

```text
place value identification
-> quantify how much the whole number changes when a digit changes

comparison
-> missing digit that makes an inequality true

midpoint / distance
-> equally spaced markers or closest-to-landmark

rounding procedure
-> smallest value in a rounding band

clue construction
-> select which candidate satisfies all clues

digit formation
-> count all valid numbers under constraints

Roman numeral recognition
-> decode, operate, and re-encode

expanded form
-> compose from nonstandard place-value groups

successor boundary
-> nth number after crossing the boundary
```

## 6. Self-generated representation is evidence

In Round 2, `no supplied representation` does **not** mean `no drawing allowed`.

If the child independently decides to create a useful representation, that is positive transfer evidence.

Track examples such as:

```yaml
selfGeneratedRepresentation:
  used: true
  type: number_line
  appropriate: true
```

Useful self-generated tools include:

- number line;
- place-value columns;
- digit slots;
- clue board;
- ordered list;
- case table;
- balance bars;
- crossing-out invalid options.

The long-term goal is not `solve without pictures`.

The goal is:

> choose and construct the representation that makes the mathematical structure manageable.

## 7. Round 2 Help rule

An optional Round 2 Help Book may exist, but only **after** the clean attempt.

If it is opened:

```text
Round 2 unsupported attempt
-> difficult
-> same Round 2 item converts to worked example
-> supported learning
-> fresh close practice
-> later unseen transfer required
```

The corrected Round 2 item must never be counted as independent transfer.

Suggested metadata:

```yaml
round2Item:
  itemId: NUM-R2-Q05
  initialResult: incorrect
  conceptLabelShownToLearner: false
  suppliedRepresentation: false
  selfGeneratedRepresentation: null
  helpOpened: true
  convertedToWorkedExample: true
  instructionallyExposed: true
  evidenceState: supported
  laterUnseenTransferRequired: true
```

## 8. Distractor design

Distractors should encode plausible reasoning errors rather than random numbers.

Examples:

### Place value

- face value instead of place value;
- one place shifted;
- subtract digit instead of place value.

### Comparison / inequality

- choose equal digit instead of a digit that satisfies strict inequality;
- compare from the right;
- ignore number of digits.

### Distance / equal spacing

- count points instead of gaps;
- divide by number of points instead of intervals;
- ignore boundary crossing.

### Rounding

- use wrong rounding band endpoint;
- include 84,500 when target is 84,000;
- confuse nearest hundred and thousand.

### Enumeration

- count arrangements with leading zero;
- double-count cases;
- forget parity or boundary constraint.

### Clue reasoning

- satisfy all but one clue;
- reverse a relational clue;
- optimize before satisfying constraints.

## 9. Evidence interpretation

Round 1 is concept-building evidence, not an exam percentage.

Round 2 is stronger transfer evidence because recognition cues are removed.

Suggested states:

```text
Round 1 correct unsupported
-> independent on that archetype

Round 1 converted to example
-> supported

TRY ONE correct without further scaffold
-> near-independent

Round 2 correct with no supplied help
-> independent transfer

Round 2 correct after self-generated appropriate representation
-> independent transfer; representation strategy positive

Round 2 corrected after Help Book
-> supported only

later unseen mixed success
-> independent / secure depending on retention
```

## 10. Presentation

### Round 1

- child-friendly thinking-family labels are allowed;
- questions may look different from one another;
- labels should identify a broad thinking tool, not reveal the answer procedure;
- maintain generous workspace for drawing or listing;
- keep Help separate from the initial attempt.

### Round 2

- no concept labels;
- exam-like MCQ formatting;
- enough blank space to build a representation;
- no decorative image that accidentally teaches the method;
- optional Help is in a separate book or clearly inaccessible during the clean attempt.

## 11. Non-goals

This schema does not:

- teach transfer through repetitive near-copy worksheets;
- require every Round 1 pre-IMO question to belong to a visible 3-question cluster;
- randomize Round 2 without a coverage plan;
- forbid the learner from drawing their own mathematical representation;
- count a helped Round 2 response as independent;
- equate visual support with lower difficulty;
- use the `right-brain / left-brain learner` idea as a scientific classification;
- infer a broad ability deficit from one difficult archetype.
